## タイトル: 家事メモの文字数上限はクライアントで判定し、Firestoreルールはプランに依存しない検査だけにする

* **ステータス: 承認済**
* 意思決定者: stotic-dev, Claude Code
* 日付: 2026-10-03
* 関連: [#353 家事にメモを追加できるようにする](https://github.com/stotic-dev/homete_iOS/issues/353)、[#330 強制アップデート](https://github.com/stotic-dev/homete_iOS/issues/330)、[実装方針](../strategy/housework-memo.md)

## 文脈、背景や問題点の説明

家事にメモ（テキスト＋チェックリスト）を追加するにあたり、文字数上限を「無料200文字・プレミアムは実質上限なし」とした。Issueの時点では上限をFirestoreのセキュリティルールでも強制する予定だった。

しかしメモはテンプレート・いつもの家事を通じてグループ内で共有され、書いた人と、そこから家事を作る人（完了・メモ編集の時点で初めてドキュメントが作られる）が別人になる。プランの判定をルールに置くと、同じグループ内で「書けたメモから家事を作れない」という食い違いが起きる。プランに応じた上限をどこで判定するか？

## 決定事項

* プランに応じた文字数上限（無料200文字・プレミアム5,000文字）は**クライアントで判定する**。判定に使うプランは他のプレミアム特典と同じく自分の購読状態（`SubscriptionStore.isPremium`）。
* クライアントでの判定は「メモを編集して保存するとき、文字数が上限を超えていて、かつ編集前より増えている場合」だけ拒否する。テンプレート・いつもの家事からのコピー、チェックを付けるだけの更新、完了などの状態変更では判定しない。
* Firestoreルールには**プランに依存しない検査だけ**を置く。
  * 安全上限: 1ドキュメント1MiBの制限からドキュメントを守るため、`memo.text`の長さとチェックリストの項目数に全員一律の上限を設ける。
  * 旧アプリによる消失の拒否: 既存ドキュメントに`memo`があるなら、更新後も`memo`が残っていることを必須にする。
    * ただし既存の`memo`が空（テキストもチェックリストも空）なら、消える更新も許可する。消えても失うものがなく、いつもの家事・テンプレートから引き継いだ空のメモのせいで、画面上はメモが無い家事を旧アプリ（1.0.1以前。強制アップデートを持たない）から操作できなくなるのを避けるため。
* 安全上限・消失の拒否を置くのは1家事1ドキュメントのコレクション（`Houseworks` / `HouseworkTemplates/*/MonthlyItems` / `FrequentHouseworks`）。毎週のテンプレート（`HouseworkTemplates/*/Days`）は家事を配列で持ち、ルールには配列を走査する手段が無いため検査しない。

## 考慮した選択肢

* **A. 書き込んだ本人の`Account.isPremium`をルールで`get()`して判定する**
  * プレミアムの人がテンプレートに長いメモを書くと、無料の同居人はそこから作られる家事を完了できなくなる（`create`には「文字数が増えていなければ通す」という例外を適用できない）。
* **B. グループのプラン（誰か1人でもプレミアム）を`Cohabitant`にFunctionsが書き、ルールはそれを見る**
  * グループ内の食い違いは解消するが、`syncHouseworkRetention`と`Cohabitant`のルールの変更が要る。ダウングレード後はAと同じ問題が起きる。
  * 判定の根拠が結局クライアントの書く`Account.isPremium`なので、ルールで強制しても改ざんへの耐性は上がらない。
* **C. クライアントで判定し、ルールはプランに依存しない検査だけにする（採用）**

## 決定結果

### 決定にあたり考慮したメリット

* 共有データの書き手と使い手のプランが違っても、家事の作成・完了が失敗しない。
* ルールとFunctionsにプランの概念を持ち込まずに済み、変更範囲が小さい。
* 改ざんへの耐性は、`expiredAt`やいつもの家事の件数上限と同じ水準（どちらも根拠はクライアント書き込みの`Account.isPremium`）で、選択肢A・Bと実質的に変わらない。

### 決定にあたり考慮したデメリット

* 改造クライアントなら、無料プランでも安全上限まで書ける。サーバー側でRevenueCatのエンタイトルメントを検証するまでの残存リスクとして扱う。
* 毎週のテンプレートは安全上限・消失の拒否のどちらもルールで担保できない。旧アプリがその曜日のテンプレートを保存し直すと、その曜日の家事のメモがすべて消える。#330の強制アップデートで最低バージョンを引き上げて塞ぐ。
