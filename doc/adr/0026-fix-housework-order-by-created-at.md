## タイトル: 家事の並びを、ドキュメントに記録した作成日時で固定する

* **ステータス: 承認済**
* 意思決定者: 佐藤汰一、Claude Code
* 日付: 2026-09-27
* 技術的背景: [#314](https://github.com/stotic-dev/homete_iOS/issues/314)（PR #317）で完了リストのハートからありがとうを送れるようにしたところ、送るたびに行の並びが入れ替わる問題が目立った

## 文脈、背景や問題点の説明

家事の一覧は、`HouseworkManager`がリスナーで受け取った家事を`Dictionary`で差し替えてから`values`を配列に戻して作っていた。`Dictionary.values`の順は決まっていないため、どの家事を操作しても、1件更新されるたびに一覧の並びが入れ替わっていた。
並びを固定するには並べる基準が要る。ところが家事ドキュメントには作成日時がなく、IDもランダムなUUIDなので、作った順を後から知る方法がなかった。

## 決定事項

* `Houseworks/{id}`のドキュメントに`createdAt`（作成日時）を足す
* 作成日時を付けるのは、ドキュメントを新しく作るときだけ。家事の登録、もう一度やった、テンプレート由来の未登録の家事を完了・やらないにしたとき。完了・未完了に戻すなどの更新では引き継ぐ
* `StoredAllHouseworkList`で日付ごとの一覧を作るときに、作成日時の古い順に並べる。作成日時が無い家事は先頭に置き、作成日時が同じ家事や、どちらも持たない家事はIDの順で並べる
* 既存のドキュメントは移行しない。`createdAt`が無ければ`nil`として読む

## 考慮した選択肢

* 作成日時をドキュメントに足し、作成順に並べる（採用）
* スキーマは変えず、`HouseworkManager`で更新された家事を元の位置で差し替えて、表示中の並びだけを保つ
* スキーマは変えず、家事名→IDの順で並べる

## 決定結果

### 決定にあたり考慮したメリット

* 端末や起動をまたいでも同じ並びになり、ユーザーが家事を作った順という意味のある並びになる
* 並べる処理が`StoredAllHouseworkList`の1箇所にまとまるので、家事ボード・未完了の家事一覧・ホームのサマリーのどれも同じ並びを受け取る
* 元の位置で差し替える案では、表示中は並びが保たれても、アプリを起動し直すとFirestoreが返すID（ランダム）の順に戻ってしまう

### 決定にあたり考慮したデメリット

* 作成日時の記録を始める前に作った家事は作成日時を持たないため、作った順ではなくIDの順で一覧の先頭に並ぶ。家事の保持期限が過ぎれば自然に消えるので、移行はしない
* `createdAt`を知らない旧バージョンのアプリが家事を更新すると、全体の上書き（`setData(merge: false)`）で`createdAt`が消え、その家事は一覧の先頭へ移る（担当者の`executors`が消えるのと同じ仕組み。[ADR-0023](0023-housework-multiple-executors-with-allocated-points.md)）。並びが1回変わるだけで、データは失われない
* テンプレート由来の家事は、完了・やらないにした時点で初めてドキュメントが作られるため、作成日時はテンプレートを設定した日時ではなく、初めて操作した日時になる。未完了のうちはテンプレートの順で、登録済みの家事の後ろに並ぶ
