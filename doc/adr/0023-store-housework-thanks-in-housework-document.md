## タイトル: 家事の「ありがとう」を、家事ドキュメントのフィールドに記録する

* **ステータス: 承認済**
* 意思決定者: 佐藤汰一、Claude Code
* 日付: 2026-09-27
* 技術的背景: [#314](https://github.com/stotic-dev/homete_iOS/issues/314) 家事ボードの完了リストで、ありがとうを送ったかを一目で分かるようにしたい。方針は[doc/strategy/complete-list-thanks-status.md](../strategy/complete-list-thanks-status.md)

## 文脈、背景や問題点の説明

今の「ありがとう」はPush通知を送るだけで、送ったことがどこにも記録されない。完了リストの行ごとに送信済みかを出すには、家事ごとに「誰が・どのコメントで送ったか」を保存する必要がある。
コメントは可変長で、1つの家事に複数の同居人から届くため、1つのドキュメントに収まるかが懸念だった。

## 決定事項

* `Houseworks/{id}`のドキュメントに`thanks`フィールドを足し、送った人のユーザIDをキーにした辞書（`{ comment, sentAt }`）で持つ
* コメントは200文字までに制限する
* ありがとうの書き込みは、ドキュメント全体の上書き（`setData(merge: false)`）ではなく、`thanks.<送った人のID>`のフィールドだけを`updateData`で更新する
* 家事を未完了に戻したときは`thanks`を空にする
* 既存のドキュメントは移行せず、`thanks`が無ければ空として読む

## 考慮した選択肢

* 家事ドキュメントのフィールドに持つ（採用）
* 家事ドキュメントの下にサブコレクション`Thanks/{送った人のID}`を作る
* 家事ドキュメントには送った人のIDの配列だけを持ち、コメントはサブコレクションに持つ

## 決定結果

### 決定にあたり考慮したメリット

* サイズの懸念は実質ない。上限は1ドキュメント1MiBで、200文字のコメント（UTF-8で約600バイト）なら100人から届いても約60KBに収まる
* 一覧の表示に必要な情報が、今の`Houseworks`のリスナー1本で揃う。サブコレクションにすると、家事ごとにリスナーを張るか、コレクショングループクエリとそのためのインデックス・ルールを足す必要がある
* 送った人のIDをキーにするので、同じ人が何度送っても1件にまとまり「1人1家事1回」が自然に守られる
* フィールド単位で更新するので、2人が同時に送っても互いの記録を上書きしない

### 決定にあたり考慮したデメリット

* 家事のほかの操作（未完了に戻すなど）はドキュメント全体を上書きするため、手元の古い`thanks`で上書きする競合が起こりうる。ただし完了済みの家事を上書きする操作は「未完了に戻す」だけで、その場合は`thanks`を消す仕様なので実害はない。完了済みの家事を全体上書きする操作を今後足すときは、この競合を考慮する必要がある
* セキュリティルールでは`thanks`の中身（キーが送った本人か、文字数が上限以内か）を検証しない。同居人グループのメンバーなら家事ドキュメント全体を書き換えられる今のルールと同じリスク水準にとどまる
* 家事ごとに届いたコメントをすべて1ドキュメントに持つため、コメントの閲覧に別の権限を設けたくなった場合はサブコレクションへの移行が必要になる
