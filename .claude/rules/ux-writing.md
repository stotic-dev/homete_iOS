# UXライティングのルール

ユーザーに見えるテキスト（`Text`、ボタンラベル、アラートメッセージ、`LocalizedStringKey`など）を新規に書く・修正するときは、hometeのボイス&トーンに合わせる。

> 経緯: RevenueCat Paywallの訴求文言が英語からの直訳調で「機械的」「中国語みたいになっている」と指摘され、hometeのアプリ内文言のトーンに合わせて書き直した（`doc/premium_plan.md`参照）。そこで得た基準をコード側の文言にも適用できるよう明文化する。

## 基本原則

### 1. 敬体で、結果・メリットを伝える言い方にする

命令形や体言止めの「〜する」で終わる文は直訳調に見えやすい。「〜できます」「〜になります」のように、ユーザー視点での結果を伝える言い方にする。

| NG（命令形・体言止め） | OK（敬体・結果ベース） |
|---|---|
| 誰が何をしたかを確認する | 誰が何をしたか、ひと目で分かります |
| より公平なルーチンを構築する | 家事の分担が、もっと公平になります |

### 2. 体言止めの漢語を並べただけの表現を避ける

短い箇条書き・ラベルであっても、2〜4字熟語を機械的に連結した表現（「全貢献履歴」「長期的な世帯トレンド」「広告なしの体験」など）は避け、人が話す言葉として自然な文にする。

| NG | OK |
|---|---|
| 全貢献履歴 | すべての貢献履歴を、いつでも振り返れます |
| 長期的な世帯トレンド | 長期的な傾向から、家事の偏りに気づけます |
| 広告なしの体験 | 広告が表示されません |

### 3. 英語の構文をそのまま日本語化しない

翻訳元がある場合、原文の語順・品詞をなぞらず、意味を汲んで日本語として自然な文を書く（例: `"Check who did what"` → 「誰が何をしたかを確認する」ではなく「誰が何をしたか、ひと目で分かります」）。

### 4. 訴求内容と機能の実態を一致させる

宣伝・訴求文言は、その機能が実際にその条件（無料/プレミアム等）で提供されているかをコードで確認してから書く。無料で使える機能をプレミアム限定であるかのように書かない。「今後追加される機能も使える」のように実体を伴わない将来価値の訴求を追加する場合は、実装側で解放の仕組みがあるかを確認し、無い場合はその旨を認識した上で扱う。

### 5. 日本語を足す・変えたら、同じ変更で英訳も入れる

文言は日本語をそのままキーにしてString Catalog（各モジュールの`Localizable.xcstrings`）で英訳を引いている。
日本語を書き換えると別のキーになり、**英語の端末では書き換えた文言だけが日本語のまま表示される**（ビルドもテストも通るので気付けない）。

- 変更後の日本語のキーに英訳（`en`）を入れ、書き換える前の古いキーを消す
- 英訳は日本語を1語ずつ置き換えず、英語のアプリとして自然な言い方にする（原則3の逆向き）。用語は既存の訳にそろえる
- `make check-translations`が通ることを確かめ、Catalogを文言を変えたコードと同じコミットに含める

手順・英訳の書き方・用語の対応表は [doc/localization.md](../../doc/localization.md) が正。

## hometeらしい言葉にするための原則

homeauは「ほめる」から名付けたアプリなので、文言でも、がんばりに気づいてねぎらう気配を出す。上の原則1〜5に加えて、見出し・ラベル・空状態・プレースホルダ・キャラクターのセリフまで次の4つを守る（経緯は #403）。

### 6. ねぎらう

家事を完了したとき、ぜんぶ終わったときは、必ず一言ねぎらう。終わったことを事実として伝えるだけで済ませない。

| NG | OK |
|---|---|
| 今日の家事は全て完了しました | 今日の家事は、ぜんぶ終わりました／おつかれさまでした。ゆっくり休んでくださいね |

### 7. 押しつけない

「〜しましょう！」のような指示口調をやめ、「〜すると、〜できます」と結果を伝える。誘うときは「〜しませんか」にする。

- 感嘆符は1画面に1つまで。使うときは全角の「！」にする（半角の「!」は使わない）
- 空状態では、何をすると何が表示されるかを伝える

| NG | OK |
|---|---|
| パートナーを登録して、家事を分担しましょう！ | パートナーを招待すると、家事を分け合えます |
| 感謝を伝えましょう！ | ひとこと添えてみませんか（例：助かったよ） |

### 8. ふつうの言葉を使う

サマリー・貢献度・頑張り度・コンフリクトのような、業務アプリや開発者の言葉を見出し・ラベルに使わない。人が話すときの言葉にする。

| NG | OK |
|---|---|
| 今日の家事サマリー | 今日の家事 |
| 10月の家事貢献度サマリー | 10月のがんばり |
| 頑張り度 | どれくらいがんばりましたか |
| 保存時にコンフリクトすると | 同時に保存すると |

### 9. アプリとキャラクターを分ける

アプリの文言は敬体にする。くだけた口調（「〜だよ」「〜してね」）は、イメージキャラクター「ほめっと」の吹き出しの中だけで使う。

## ほめっとのセリフ

ほめっとは、家事をした人を見ていて喜ぶ役。家事をしたのは人なので、ほめっとが手柄を取らない。

- 人を比べない。ランキングの順位にはコメントしない
- サボりを責めない、急かさない
- 同じ場面でも数種類のセリフを用意し、ランダムに出して飽きにくくする
- 課金（Paywall・プラン管理）、退会・ログアウト・削除の確認、利用規約などの法務画面、家事一覧の行ごとには出さない

| 場面 | セリフの例 |
|---|---|
| 家事を完了したとき | やったね、洗濯おわり！ +20pt |
| ありがとうが届いたとき | はなこさんから「ありがとう」が届いたよ |
| ぜんぶ終わったとき | 今日はもうおしまい。おつかれさま |
| 読み込みエラー | うまく読み込めなかったみたい。電波のいいところで、もう一度ためしてみてね |

## 適用範囲の補足

このルールはSwiftコード中の文言だけでなく、RevenueCat Paywallの訴求文言（`billing-product-ops`スキルで編集するダッシュボード側のコピー）にも同じ基準で適用する。Paywallの文言を編集する際は、変更後に対象機能の提供条件をコードで確認すること（原則4）。
